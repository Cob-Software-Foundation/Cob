# Cob Language v0.2.0

## Areas of Improvement for v0.2.0

### Boolean Operators
and, or, and not now work naturally in conditions (if, elif, while). They short-circuit like Python - the right side is not evaluated when the left side decides. They work in if/elif/while blocks, and a variable named not, and or still works. They are turned into plain if statements over a hidden variable (__condN), so the cache format and the C that popcorn_comp emits are unchanged.

### Dynamic Linking Friction
Because popcorn_comp links standard library modules dynamically and bakes in an rpath, distributing standalone executables that use shuck still requires shipping lib/ alongside them or configuring COB_STDLIB -- this breaks static musl builds.

Fixed: popcorn_comp now defaults to --static-stdlib when libcob_stdlib.a exists, so compiled programs are standalone by default and do not need to ship lib/ or set COB_STDLIB. This is the default for musl targets; use --dynamic-stdlib to opt out.

Note: pantry, granary and barn wrap C libraries and stay as shared libraries.

### Manual Handle Cleanup
Lists (bushel), arrays (furrow), and databases (pantry) now rely on automatic handle cleanup instead of manual _free / _close calls, which is easy to forget in a high-level scripting-style language.

Fixed: Automatic memory handle management:
- VarTable.replace() automatically frees old handle values on variable reassignment
- Recipe return cleanup frees handles in recipe locals
- Program exit cleanup frees all global handles
- Compiled code uses cob_harvest_registered() and cob_handle_free_value() / cob_handle_free_all()

Note: No more needing to remember _free / _close calls for lists, arrays, and databases.

### Trailing Comments
Requiring # comments to be on their own separate lines is an unusual restriction that will trip up people coming from Python.

Fixed: Comments can now follow code directly: set x = 1 # note works; a # inside a string is still just text.
