# Cob Language v0.0.7

## Overview

The headline feature is conditionals. Cob now has `if`, `elif` and
`else`:

```
set score = 85
if score >= 90:
    pop("grade: A")
elif score >= 80:
    pop("grade: B")
else:
    pop("keep practicing")
```

Both tools support it, and they print identical output for the same
program:

* **`cob_interp`** parses, caches and runs it.
* **`popcorn_comp`** compiles it to a plain C `if (...) { ... } else
  { ... }`.

## Added

* **`if <condition>:`** runs its indented block when the condition is
  true. The condition grammar is exactly `while`'s: `==`, `!=`, `<`,
  `>`, `<=`, `>=` on two numbers or two strings, or a bare expression
  as a truthiness test (non-zero for a number, non-empty for a string).
  Comparing a string to a number still warns and evaluates to false.
* **`elif <condition>:`** and **`else:`** may follow an `if` at the
  SAME indentation. Any number of `elif`s, at most one `else`.
* Blocks nest freely: `if` inside `if`, inside `while`, and `while`
  inside `if`.
* `if`, `elif` and `else` are now reserved words, so an `extern` can no
  longer be declared with one of those names (same rule as `while`,
  `set`, `pop`, ...).
* Clear syntax errors, each with a line number:
  * `'else' without a matching 'if' at the same indentation`
  * `'elif' without a matching 'if' at the same indentation`
  * `malformed condition in if statement` (or `elif`)
  * `expected ':' to open if block` (or `elif`)
* An "if / else" example on the in-browser playground, and `if` on the
  website's release notes and download page.

## Changed

* **`.strawberry` cache format bumped from `COBSTRW7` to `COBSTRW8`.**
  A new statement kind (`STMT_IF`) was appended, with the condition
  followed by the then-block and the else-block. Existing caches are
  detected as stale and rebuilt automatically the next time a script
  runs (you will see one `cache ... unreadable, reparsing source` note
  per script). Nothing needs to be deleted by hand.
* `elif` is not a separate kind in the cache or the compiler: the
  parser turns it into an `if` nested inside the previous `else`, so
  the cache reader/writer and the code generator only ever deal with
  if/else.

## Verified this session

* A test script (`tools/tests/if_statements.cob`, with its expected
  output in `tools/tests/if_statements.expected`) covering if, if/else,
  an if/elif/elif/else chain, an `if` nested inside an `elif` branch
  inside a `while` loop, string equality and inequality, and the
  truthiness of `0` and `""`, produces byte-identical output cold,
  against its own `.strawberry` cache, and as a native binary built by
  `popcorn_comp`.
* `cob_interp` compiles clean under `-Wall -Wextra -Wpedantic` and runs
  clean under AddressSanitizer + UndefinedBehaviorSanitizer +
  LeakSanitizer on the valid program (cold and cached) and on seven
  malformed programs, including errors in the middle of an
  `if`/`elif`/`else` chain (a bad `elif` condition, a bad statement
  inside an `else` body, a second `else`, a missing colon, an `else`
  with no `if`), which free a half-built chain.
* A `COBSTRW7` cache and a truncated `COBSTRW8` cache are both ignored
  with a note and the script is re-parsed correctly, rather than
  misread.
* The existing arithmetic stress script still runs, and the widget
  smoke script still runs in a plain `make cob_interp` build.
* The `-DCOB_WASM` configuration (the same defines `make wasm` uses)
  compiles natively and gives the same output on the test script.

## Not verified

* `make wasm` has not been run here: Emscripten is not installed in
  this environment. The code is plain C99 with no new dependencies and
  the `-DCOB_WASM` flavor was compiled natively as described above, but
  the first real `emcc` build will be whatever CI run triggers it.
  Pounce (the block-coding front end) builds from this source, so it
  inherits that gap.
* `popcorn_comp`'s `-Wpedantic` build still emits one warning about an
  over-long string literal in the C runtime preamble. It was already
  there before this release and this release did not touch it.
* Everything Windows/macOS/cross-compile-related that previous
  releases flagged as not verified on real hardware remains not
  verified; this release touched none of that code.
* The website changes (`docs/index.html`, `docs/download.html`,
  `docs/play/index.html`) were edited but not opened in a browser, and
  the new playground example has not been run in the WebAssembly
  playground.
* The full CI suite (`ci.yml`, `build.yml`, the Docker stress image)
  has not been run on this change.
