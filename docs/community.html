Publish a library

The package registry lives in its own repository, pixel-pulse-labs/cpi, served for free via GitHub Pages — static JSON files, no server to run. Add your package's metadata there and it's installable with a single command.

# anyone can install what you publish
$ farmer harvest your-library

# then, in a .cob file
shuck your-library

Before you open a PR

A few things that make review faster, based on how the codebase is actually structured today:

  • Keep changes scoped to one tool where possible — cob_interp, popcorn_comp, and farmer are deliberately independent, and a PR touching all three is harder to review than three small ones.
  • Compile clean with gcc -std=c99 -Wall -Wextra before opening the PR — this is the bar the maintainers hold their own changes to.
  • If you're touching anything that builds a shell command string (popcorn_comp's compiler spawning is the current example), test it on Windows specifically — that's where quoting bugs actually surface.
  • State plainly what you did and didn't verify, the way the project's own release notes do. "Compiles clean" and "tested end-to-end on a real machine" are different claims — say which one is true.
