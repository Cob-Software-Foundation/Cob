Cob is a small corn-themed language with an interpreter, a native compiler, and a package manager — built to boot fast, compile to a real standalone binary, and stay out of your way.

One toolchain, three jobs

Each tool does exactly one thing — run a file, build a binary, or fetch a library — and hands off cleanly to the next.

cob_interp file.cob

Interpret

Runs a .cob file directly, with a fast-boot .strawberry bytecode cache so repeat runs skip re-parsing. Start it with no file for an interactive REPL.

popcorn_comp file.strawberry -o out

Compile

Transpiles to C and spawns a real compiler to produce a standalone native binary — recipes and the whole standard library included. Cross-compile with CobOS/CobArch.

farmer harvest name

Fetch

Installs a .cob library from the package registry, zip-slip protected, ready to shuck straight into your program.

Recent history

0.0.9 Functions, a REPL, and a real standard library

recipe add(a, b): defines a function and serve a + b hands a value back — like Python's def and return. Parameters and every name a recipe sets are local to it, recipes may recurse (500 calls deep, then a warning instead of a crash), and a wrong call is an error before the program starts, with its line number. Run cob_interp with no file for an interactive session where a bare expression prints its value. And the language got smaller on purpose: input, SQLite, windows and Tcl/Tk are no longer built into the interpreter. They are shared libraries (porch, pantry, barn, tassel) beside new ones for numbers, text, time and files — each loaded with shuck, every name corn themed. The compiler can finally compile the SQLite and window programs, and two compiler bugs are fixed: set s = s + "x" lost the old string, and operands that print could run right-to-left. The .strawberry cache format bumped to COBSTRW10.

0.0.8 Programs can finally ask questions

Until now a Cob program could only talk. set name = input("What is your name? ") prints the prompt, waits for a line of typing, and hands it back as a string; input_int(<prompt>) does the same and parses the line as a whole number (a non-number, or the end of the input, gives 0, with a warning for the first). The prompt is optional — input() is fine — and at the end of the input input() returns an empty string, so piping a file into a program just works. Shipped in both cob_interp and popcorn_comp, which behave identically, and in the playground. The .strawberry cache format bumped to COBSTRW9, so older caches are rebuilt automatically. Also fixed: a small leak in compiled programs that tested a string for truthiness (if name:).

0.0.7 if / elif / else

Cob finally has conditionals. if <condition>: runs an indented block when the condition is true; optional elif <condition>: and else: blocks follow at the same indentation. Conditions work exactly like while conditions (comparisons on two numbers or two strings, or a bare truthiness test), and blocks nest freely inside each other and inside loops. Shipped in both cob_interp and popcorn_comp, which print identical output for the same program. The .strawberry cache format bumped to COBSTRW8, so older caches are rebuilt automatically.

0.0.6 A C API / FFI, and a WebAssembly playground

extern <name>(...) from "<lib>" binds a Cob name to an exported C function with one fixed signature (see include/cob.h) — cob_interp resolves it eagerly with dlopen/dlsym, while popcorn_comp emits a real forward declaration and links the library directly at compile time, no dlopen in the compiled binary at all. Also new: the pure-language core compiles to WebAssembly, powering an in-browser playground — desktop-only keywords (SQLite, _cobwindow, and now extern) no-op there with a one-time notice instead of crashing, so the rest of the script keeps running.

0.0.5 SQLite, native windows, and widgets — all with zero autoconf

Plain `make` now builds cob_interp_full: SQLite (sql_open/sql_exec/sql_query/sql_close) plus a native window backed by raylib (window_open/window_label/window_wait/window_close), with raygui-backed window_button/window_slider/window_textbox for real, interactive buttons, sliders, and text boxes. Tcl/Tk moved to the separate `cob_interp_db` build — still available, just no longer in the default dependency chain.

0.0.4 Strings, and pop() that can finally print a variable

Cob variables were integers only since the language's first release. This adds strings: pop(<expr>) accepts any expression instead of only a literal, "+" concatenates, and ==/!=/</>/<=/>= work on two strings the same way they already did on two numbers. Shipped in both cob_interp and popcorn_comp — a compiled binary behaves identically to the interpreted program, including matching type-mismatch warnings.

0.0.3-bug-fix-2 Project moved to the Cob-Software-Foundation GitHub org

All three repos (Cob, cpi, and the new Cob-Docs) now live under Cob-Software-Foundation instead of pixel-pulse-labs. Every hardcoded repo/registry URL was updated, including farmer's default package registry (COB_FARMER_DEFAULT_BASE_URL), so a plain `farmer harvest <package>` resolves correctly without setting $COB_FARMER_BASE_URL by hand.

0.0.3-bug-fix-1 popcorn_comp: fixed a Windows-only cmd.exe quoting bug

Auto-resolving a bundled zig/ folder next to popcorn_comp could produce a compiler command cmd.exe corrupted before it reached the shell. Explicit --cc/$CobCC compiles were never affected.

0.0.3 Project Obsidian Falcon

popcorn_comp dropped its embedded TCC in favor of spawning a real compiler (Zig by default); farmer moved to in-process zip extraction with zip-slip protection; SQLite, Tcl, and Tk vendored (not yet wired into the language).
